# AI Chat Memory

**简体中文** | [English](README.en.md)

把浏览过的 AI 对话保存到本机，方便离线检索、整理和导出。

AI Chat Memory 是一个基于 Manifest V3、TypeScript、React 和 Vite 的 Chrome
扩展，支持 ChatGPT、Gemini 和 DeepSeek。它按设置保存当前打开的对话，提供独立的
对话管理页面，并将记录存放在当前浏览器配置文件的 IndexedDB 中。

日常使用不需要 API Key、Node.js 或本地服务。项目没有自建服务器、遥测或云同步；
可选的共享目录由用户手动授权。

> 默认开启自动保存，但**首次自动收录仅限能确认原生置顶状态的对话**。
> 未置顶的对话可以手动采集。扩展不会遍历或批量下载账号里的全部历史对话。

## 主要功能

- **三平台对话归档**：保存用户提问和助手正文，按平台分别控制自动保存。
- **当前对话侧边栏**：查看采集状态、手动更新、标记重要、设置图片和文件保存权限。
  浮动入口默认位于 `top: 70px; right: 10px`，可以拖动；打开侧边栏时入口隐藏，关闭后恢复。
  侧边栏可以调整宽度和锁定。
- **独立对话管理器**：离线搜索，按平台、账户、环境、重要标记和时间筛选，查看和删除记录。
- **多种采集方式**：ChatGPT 和 Gemini 均支持本页、分享页的 DOM 和接口采集。
- **附件本地副本**：保存可读取的对话图片；普通文件按对话授权，缺失文件可手动从本地补齐。
  已保存的文本附件支持离线预览。
- **导出与备份**：单条对话或部分消息导出 Markdown，按环境批量导出 Markdown ZIP，
  使用 JSON 备份和恢复正文及已保存的附件。
- **可选共享目录**：同一台机器上的多个 Chromium 浏览器配置文件，
  可以通过手动授权的同一目录查看彼此的归档。

## 平台支持

| 能力 | ChatGPT | Gemini | DeepSeek |
| --- | --- | --- | --- |
| 当前对话 DOM 保存与增量更新 | 支持 | 支持 | 支持 |
| 原生置顶识别与首次自动收录 | 支持 | 支持 | 暂无稳定置顶证据 |
| 手动滚动读取完整对话 | 支持 | 支持 | 使用当前页面采集流程 |
| 手动提供分享链接后采集 | 支持 | 支持（DOM / 接口） | 尚未集成 |
| 显式启动的接口采集 | 支持 | 支持 | 尚未集成 |
| 已保存记录的管理与导出 | 支持 | 支持 | 支持 |

开启“仅置顶对话”时，DeepSeek 不会首次自动收录，可以手动保存；已经保存的对话，
在对应平台自动保存开启时仍可继续更新。各平台的附件支持取决于页面实际渲染的资源
及其可读取性，不能保证每个附件都能复制。

## 安装

需要 Chrome / Chromium 118 或更新版本。当前尚未专门完成 Chrome 118 最低版本和跨电脑兼容性验证。

### 使用已有安装包

如果已有 `ai-chat-memory-<version>.zip`：

1. 将 ZIP 解压到一个固定目录，确认目录内直接包含 `manifest.json`。
2. 打开 `chrome://extensions`，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的目录。
4. 打开或刷新一个支持的 AI 对话页面。

ZIP 根目录直接包含扩展文件，没有额外的 `dist/` 层。

### 从源码构建

构建需要 Node.js 22 和 npm。在项目根目录运行：

```bash
npm ci
npm run typecheck
npm run lint
npm run build
```

构建完成后，在扩展管理页加载项目的 `dist/` 目录。项目根目录同时生成
`ai-chat-memory-<version>.zip`，具体版本以 `package.json` 为准。

**更新扩展后，需要重新加载扩展并刷新已经打开的 AI 页面。** 已打开页面中的旧内容脚本
不会自动替换；版本不一致时，扩展会暂停采集并提示刷新。

## 快速开始

1. 打开一条 ChatGPT、Gemini 或 DeepSeek 对话，等待正文显示。
2. 点击页面边缘的 AI Chat Memory 浮动按钮，打开当前对话侧边栏。
3. 手动点击采集按钮，或在自动保存开启时由符合置顶条件的对话触发首次收录。
4. 在侧边栏确认保存结果。点击浏览器工具栏中的扩展图标，打开完整对话管理器。
5. 在管理器中搜索、筛选、标记重要或导出已保存的内容。

设置页可以控制全局自动保存、各平台开关、首次仅收录置顶对话、附件权限和共享目录。
“重要”是本地分类标记，不等同于网站置顶，也不会自动授予附件权限。

### 自动更新和手动采集

普通自动更新只读取当前页面已经渲染的对话，等待内容稳定后保存，不主动滚动或刷新页面。
网站的虚拟列表可能只挂载部分消息，因此“当前已保存”不等于已备份整个账号的历史记录。

ChatGPT 和 Gemini 的手动完整 DOM 采集会滚动当前对话，读取更多渲染窗口并核对连续性，
成功后停留在已验证的对话顶部。无法确认身份或完整性的内容不会被当作完整结果保存。
Gemini 生成或编辑中的回复不会被标记为完整存档，请结束后再采集。

### ChatGPT / Gemini 分享页采集

1. 在 ChatGPT 或 Gemini 网站上手动创建或更新**整条对话**的分享链接。
2. 回到原对话的扩展侧边栏，选择分享页模式，粘贴该链接并开始采集。
3. 扩展打开一个属于本次任务的标签页，读取分享页并与原对话核对后补入记录。
4. 如果提示后台渲染暂停，点击“打开分享页 ↗”，保持采集页可见，随后回原侧边栏查看结果。

扩展不会替你创建分享。分享链接的可见范围由相应网站决定；不希望公开的内容应使用
当前页面采集。旧分享可能不包含最新消息，补齐前需要在网站上手动更新分享。

### ChatGPT / Gemini 接口采集

Gemini 在当前对话侧边栏提供“本对话 DOM”“分享页 DOM”“本对话接口”“分享页接口”四种选择。
分享页接口接受手动粘贴的 Google 短链接或完整分享地址；短链接仅在启动任务时展开，
不携带登录凭据。分享页 DOM 不使用调试权限、不刷新原对话；它核对完整滚动边界、连续问答和原页唯一正文锚点，并保留已有正文、附件及账号归属。接口采集的完整历史须同时通过原生父链、
所选回答、历史终点及页面正文和代码核对；无法解释的新显示组件会停止保存。
Google 的隐藏显示注释和建议按钮的动作参数不会进入正文，接口时间字段不会用作消息时间。
Gemini 校验失败时保留原记录，可重试或选择本页 DOM；不会提供异常候选强行保存。
分享采集还需在原对话中显示与分享末轮一致的问答，无法绑定时请更新整条对话分享后重试。

接口采集需要明确选择并启动，普通自动更新始终使用 DOM。扩展只读取本次目标页面
自然返回的响应，不主动调用或重放对话私有接口。

当前页面接口采集会在确认没有未发送草稿、选中或上传中的附件、编辑和生成状态后，
执行一次受控刷新。请先结束编辑和生成。打开 DevTools 或其他调试工具可能中断任务。

只有消息身份、分页或分支证据和页面锚点核对通过，内容才会按已验证结果保存。
ChatGPT 异常任务若提供可安全绑定的候选内容，可以在发起侧边栏中明确确认保留；这类内容标记为
**待补全**，不能视作完整备份。确认时保留已有正文和附件，不复制新附件。
只有后续完整采集实际覆盖待补全消息，才会清除标记。

## 图片、文件和备份

图片默认开启保存，可以按对话覆盖。普通文件需要单独授权；开启权限后，需再次手动采集
才能补齐可读取的附件。关闭权限会阻止后续读取，但不会删除已有的本地副本。

- 单个附件上限可设为 1 / 2 / 5 / 10 MB，硬上限为 10 MB。
- 每条对话的附件解码后总量上限为 30 MB。
- 页面只有文件名、下载地址不可用、资源超限或未授权时，只保存元数据和状态。
- 已保存 `.txt`、`.md`、`.markdown` 文件可离线预览。预览最多显示 200,000 个字符，
  复制和下载仍使用完整内容。
- 普通文件缺少副本时，可在管理器详情中选择“从本地补齐”，选择同名原文件。

| 用途 | 格式 | 包含内容 |
| --- | --- | --- |
| 阅读、分享单条对话或部分消息 | Markdown | 正文、附件名称和状态，不包含附件二进制 |
| 批量阅读归档 | Markdown ZIP | 按环境分目录，每条对话一个 Markdown 文件，不包含附件二进制 |
| 对话备份和恢复 | 版本 1 JSON | 账户、对话、重要标记、待补全状态及已保存的附件数据 |

Markdown 按已保存的消息顺序导出，不生成 AI 摘要。JSON 是对话数据备份，
**不是完整浏览器环境备份**：不包含显示设置、自动保存排除记录、共享目录授权或本地分享链接偏好。

删除最后确认为置顶的本地对话时，会同时加入自动保存排除列表，防止马上被重新收录。
未置顶记录只删除、不加入排除。可以在设置中解除排除，或通过手动保存、JSON 导入恢复。

## 隐私与权限

完整处理说明见[中英双语隐私政策](PRIVACY.md)。扩展管理器设置页也提供离线政策入口。

### 数据存放在哪里

正文、附件、账户标签和设置存放在当前 Chrome 配置文件的 IndexedDB 中，数据库名为
`AIChatMemoryDB`。不同配置文件的数据相互隔离。已保存的列表、搜索、详情和附件副本
可以离线查看；尚未复制的远程附件仍需在可读取时补齐。

扩展不会上传对话、搜索、日志或分析数据。数据仅在用户明确导出，或授权共享目录时，
由扩展写出当前浏览器配置文件。导出和共享目录中的 JSON、附件数据没有额外加密；
请选择可信目录，自行决定是否放入第三方同步盘。

扩展不读取认证 Cookie、令牌或认证存储，不扫描其他远程对话，不自动点击网站控件，
不注入远程代码。账户标签可能来自页面显示的名称；Gemini 也可能使用页面显示的邮箱
区分账户，这些信息保存在本地，提交问题时请遮盖。

### 为什么申请这些权限

| 权限或页面范围 | 用途 |
| --- | --- |
| 三个支持网站的内容脚本 | 读取当前渲染对话，显示浮动入口与侧边栏 |
| `debugger` | 用户明确启动 ChatGPT 或 Gemini 接口采集或验证后，读取绑定目标自然返回的响应 |
| Google / OpenAI 图片域名访问 | 有界读取对话中已渲染的图片，创建本地副本 |
| Gemini 公开分享域名 | 仅展开手动提供的短分享链接，不携带登录凭据 |
| 用户手动选择的文件系统目录 | 可选的跨浏览器环境本地镜像 |

图片域名范围为 `lh3.googleusercontent.com`、`lh3.google.com`、
`*.oaiusercontent.com` 和 `images.openai.com`。扩展还可在附件授权和大小限制内，
读取对话页面已经提供的普通文件下载地址。权限明细见
[manifest](public/manifest.json)，边界与实现见 [ARCHITECTURE.md](ARCHITECTURE.md)。

### 可选共享目录

在每个需要共享的浏览器环境中，分别打开设置，选择同一个本机目录并授权读写，再为环境命名。
管理器默认只显示当前环境，需要通过“显示环境”显式选择其他环境。

```text
AIChatMemory/
  ai-chat-memory.json
  environments/
    env-<UUID>/
      environment.json
      accounts.json
      conversations/
        <conversation-id>.json
```

IndexedDB 仍是当前环境的主存储，共享目录不可用不会撤销成功的本地保存。
浏览器重启后可能需要再次授权。此功能是同机目录镜像，不是扩展提供的云同步。

删除其他环境的共享记录会写入删除请求；来源环境使用 0.5.35 或更新版本、
再次运行并拥有目录读写权限时，会删除相应本地记录和附件。清空当前环境数据会保留
环境身份和目录连接，并将当前环境镜像为空。重要记录建议先导出 JSON 备份。

## 已知限制与排查

| 情况 | 说明或处理方式 |
| --- | --- |
| 打开对话后没有首次自动保存 | 检查全局和平台开关、仅置顶限制及排除列表；也可手动采集 |
| 长对话只有部分消息 | 自动更新依赖已渲染窗口；ChatGPT / Gemini 可尝试手动完整采集 |
| 分享页采集等待继续 | 打开任务拥有的分享页，保持其可见，不要另外创建采集标签页 |
| 接口采集中断 | 检查草稿、附件、生成状态，关闭冲突的 DevTools 后重新发起 |
| 附件只有名称没有下载副本 | 核对授权、资源可用性及大小限制；重新采集或从本地补齐普通文件 |
| 更新后提示版本不一致 | 重新加载扩展，再刷新已打开的 AI 标签页 |
| 消息没有时间 | 仅保留平台真实暴露的来源时间，不用采集、导入或同步时间代替 |

ChatGPT 当前可在用户手动打开助手回复的原生更多菜单后，读取分钟精度的回复时间。
用户提问时间、Gemini 正文中的日期，以及接口响应中的时间字段不会被推定为消息时间。

网站布局和渲染方式会变化，不能保证所有历史版本、交互组件、分支和附件都能完整归档。
遇到无法核对的身份或完整性时，扩展会保留失败或待补全状态，不把它当作已完成。
本项目为独立工具，与 OpenAI、Google 和 DeepSeek 无官方隶属关系。

## 开发与验证

```bash
npm run typecheck
npm run lint
npm run build
```

完整构建会依次生成界面、内容脚本和后台 Service Worker，在 `.dist-build/` 中运行验证，
通过后发布 `dist/` 和版本 ZIP。构建验证覆盖站点提取、置顶、对话窗口合并、采集完整性、
附件、导出、共享删除和消息展示等行为。打包先验证新 ZIP，再清理本项目旧版本 ZIP；
失败时保留最后有效安装包。

迭代时可以运行相关的聚焦验证，例如：

```bash
npm run verify:chatgpt
npm run verify:gemini
npm run verify:network-evidence
npm run verify:capture-windows
npm run verify:attachments
npm run verify:exports
npm run verify:repository
npm run verify:privacy
npm run verify:license
```

开发服务器 `npm run dev` 用于界面开发预览；实际扩展功能需要构建并加载 `dist/`。
不要手动编辑生成的 `dist/`。任何可分发改动都需要同步递增 `package.json`、
`package-lock.json` 根条目和 `public/manifest.json` 的版本。

### 目录结构

```text
src/
  adapters/      各平台 DOM 解释、选择器与站点行为
  content/       页面观察、采集编排与浮动面板
  background/    Service Worker、消息处理与采集协调
  db/            IndexedDB、设置和任务状态
  services/      对话、账户、附件与共享目录服务
  panel/         React 管理器和当前对话界面
  shared/        跨上下文类型、消息协议和完整性工具
scripts/         构建、打包与回归验证
public/          扩展 manifest 与静态资源
```

### Git 提交范围

提交源码、静态资源、构建与验证脚本、依赖锁文件及必要的项目说明。
`.gitignore` 明确排除 `dist/`、`.dist-build/`、依赖目录、ZIP 安装包、`doc/`、
`docs/`、`plan/`、`plans/`、内部实现计划、本地研究数据、日志、缓存及本机配置。
内部文档不参与构建，公开检出无需这些文件也能运行验证。不要用 `git add -f` 强行提交这些文件。

`verify:repository` 检查源码、注释、脚本、公开根文档与静态资源中的受限环境品牌名，
完整构建还会检查待发布产物。存在 Git 仓库时，还会拒绝已跟踪或已暂存的忽略文件，
防止内部文档或产物通过强制添加进入提交。

`npm run verify:secrets` 检查待公开工作文件及已有 Git 暂存区，拦截常见密钥、令牌、
个人邮箱、本机用户目录、真实对话链接及对话或会话 JSON 导出。验证脚本仅允许明确的
虚构测试账号和会话标识，不允许真实对话测试数据；报告只显示位置和规则，不打印命中内容。
此检查也在构建打包前运行。

Git 仓库中的 `npm ci` 会启用 `.githooks/pre-commit`。若之后才初始化仓库，运行
`npm run setup:git-hooks`。该钩子读取实际暂存的文件内容，并拒绝被强制添加的忽略文件。
首次提交前，使用仓库级 `git config --local user.name` 设置你选择的公开署名，
使用 `git config --local user.email` 设置 GitHub 账号 Settings → Emails 中的
GitHub noreply 邮箱；未配置时钩子会阻止提交，避免继承其他账号的私人身份。
SSH 私钥仅放在本机 SSH 目录，不放入工程。自动检查不能识别所有私人文本，提交前仍须
人工审阅暂存差异，不要绕过钩子。
